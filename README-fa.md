# PortLedger: شمارندهٔ ترافیک هر پورت

[English guide](README.md)

نام پروژه PortLedger است و دستور نصب‌شده همچنان `port-traffic` است.

این ابزار مصرف هر پورت را به‌صورت مجموع دانلود و آپلود، با واحد گیگابایت نمایش می‌دهد. شمارش روی اینترفیس عمومی سرور و در سطح IP انجام می‌شود. برای هر پورت، TCP و UDP و هر دو نسخهٔ IPv۴ و IPv۶ در یک حساب قرار می‌گیرند.

## استفاده روی سرور

دستورها را با کاربر `root` اجرا کنید. با کاربر دیگر، ابتدای دستور `sudo` بگذارید.

برای شروع شمارش یک پورت، مثلاً `8443`:

```bash
port-traffic add 8443
```

برای دیدن مصرف همان پورت:

```bash
port-traffic 8443
```

خروجی شامل این مقدارهاست:

- `Upload`: دادهٔ ورودی از مشتری به سرور.
- `Download`: دادهٔ خروجی از سرور به مشتری.
- `TOTAL`: مجموع دانلود و آپلود به گیگابایت.
- `Exact total bytes`: مجموع ثبت‌شده، برحسب بایت و بدون گردکردن.
- `Since (UTC)`: زمان شروع شمارش این پورت.

هر گیگابایت در این ابزار برابر با یک میلیارد بایت است؛ واحد خروجی `GB` است، نه `GiB`.

برای اضافه‌کردن پورت دیگر، فقط شماره را عوض کنید:

```bash
port-traffic add 2083
```

اجرای دوبارهٔ `add` برای پورتی که ثبت شده، آمار آن را صفر نمی‌کند. نمایش مصرف نیز شمارنده را صفر نمی‌کند.

برای دیدن همهٔ پورت‌های ثبت‌شده:

```bash
port-traffic list
```

برای خروجی قابل‌خواندن توسط برنامه‌ها:

```bash
port-traffic show 8443 --json
```

برای بررسی سلامت شمارنده:

```bash
port-traffic doctor
```

برای دیدن وضعیت ذخیرهٔ خودکار:

```bash
systemctl status port-traffic-sync.timer
```

## محدودهٔ شمارش و دقت

- فقط ترافیک پورت محلی روی اینترفیس انتخاب‌شده محاسبه می‌شود. نام اینترفیس را بر اساس تنظیمات سرور انتخاب کنید؛ `eth0` در دستورهای این راهنما فقط نمونه است.
- ترافیک داخلی تانل و ترافیک رابط `loopback`، اگر روی اینترفیس دیگری باشند، به حساب این پورت اضافه نمی‌شوند.
- این ابزار برای پورت‌های شنوندهٔ محلی، مانند پورت مشتری در Backhaul، ساخته شده است؛ برای مسیریابی یا پورت‌فوروارد مبتنی بر DNAT طراحی نشده است.
- بایت‌های سطح IP شامل سربرگ‌ها و ارسال مجدد هستند؛ این عدد لزوماً با حجم فایل دانلودشده یا صورتحساب شرکت میزبان یکی نیست. شمارش سخت‌افزاری روی سیم هم نیست.
- حساب هر پورت فقط زمانی متعلق به یک مشتری است که همان پورت به‌صورت اختصاصی در اختیار آن مشتری باشد. این ابزار مشتریان مشترک روی یک پورت را تفکیک نمی‌کند. با عوض‌شدن مشتری هم آمار آن پورت خودبه‌خود دورهٔ تازه‌ای شروع نمی‌کند. در این نسخه، دستوری برای حذف حساب یا صفرکردن آمار وجود ندارد.
- مصرف پیش از فعال‌کردن ابزار به آمار جدید اضافه نمی‌شود. شمارنده‌های قبلی فایروال حذف یا صفر نمی‌شوند؛ پیش از نصب، یک نسخه از قوانین و اعداد آن‌ها در مسیر پشتیبان ذخیره می‌شود. آن تصویر تاریخی، بخشی از جمع جدید نیست و نباید بدون تعیین بازهٔ مشترک به آن جمع زده شود.

## نگهداری آمار

مقدار مصرف در کرنل پیوسته شمرده می‌شود. فایل وضعیت معمولاً هر ده ثانیه ذخیره می‌شود و دستور نمایش نیز آمار زنده را می‌خواند و ذخیره می‌کند.

فایل وضعیت روی سرور:

`/var/lib/port-traffic/state.json`

فایل وضعیت با قفل بین پردازش‌ها و جایگزینی اتمی نوشته می‌شود. در بوت بعدی، پورت‌ها از همین فایل دوباره فعال می‌شوند و مجموع ذخیره‌شده حفظ می‌شود. هنگام خاموش‌شدن عادی هم دستور ذخیره اجرا می‌شود.

در قطع ناگهانی برق، خرابی دیسک یا توقف اجباری، ترافیک بعد از آخرین ذخیرهٔ موفق ممکن است از دست برود. فاصلهٔ معمول ذخیره ده ثانیه است، اما تاخیر سیستم یا دیسک می‌تواند آن را بیشتر کند. حذف یا بازنشانی خارجی قوانین فایروال نیز ممکن است فاصله‌ای در شمارش ایجاد کند. ابزار در بازسازی جدول یا تشخیص بازنشانی شمارنده هشدار ثبت می‌کند؛ چنین آماری را بدون بررسی، کامل فرض نکنید.

اگر پس از ری‌بوت، شمارنده‌های قدیمی فایروال هم برگردند، ابزار مقدار موجود را مبنای تازه می‌گیرد تا دوباره به مجموع اضافه نشود. مجموع ذخیره‌شده حفظ می‌شود، اما ترافیک پیش از این مبنای تازه ممکن است ثبت نشده باشد؛ هشدار `boot_rebase` همین محدودیت را نشان می‌دهد.

در زمان کار ابزار، نسخهٔ قدیمی جدول `port_traffic` و شمارنده‌های آن را برنگردانید. بازیابی شمارندهٔ قدیمی در همان بوت همیشه از ترافیک تازه قابل‌تشخیص نیست و می‌تواند باعث آمار اشتباه شود. فایل پشتیبان فایروال برای بررسی و بازیابیِ برنامه‌ریزی‌شده است، نه بازگردانی مستقیم در زمان شمارش.

فایل وضعیت را حذف یا دستی ویرایش نکنید. دستور `nft flush ruleset` هم شمارنده‌ها را از بین می‌برد. برای پشتیبان‌گیری از آمار، ابتدا ذخیره کنید:

```bash
port-traffic sync
```

سپس یک کپی از فایل وضعیت بگیرید:

```bash
cp -p /var/lib/port-traffic/state.json /root/port-traffic-state-backup.json
```

## نصب روی سرور دیگر

نیازمندی‌ها: اوبونتو با `systemd`، پایتون نسخهٔ ۳٫۱۰ یا جدیدتر، `nftables` و `iproute2`.

در پوشهٔ فایل‌ها:

```bash
sh install.sh
```

نصب‌کننده وابستگی‌ها را بررسی می‌کند، تست‌های واحد را اجرا می‌کند و پیش از جایگزینی فایل‌های موجود از آن‌ها پشتیبان می‌گیرد. قوانین قبلی فایروال پاک نمی‌شوند و سرویس تانل ری‌استارت نمی‌شود.

سپس اولین پورت را با نام اینترفیس صحیح فعال کنید:

```bash
port-traffic add 8443 --interface eth0
```

در صورت حذف `--interface`، اینترفیس مسیر پیش‌فرض IPv۴ انتخاب می‌شود. اگر چند مسیر پیش‌فرض با اینترفیس‌های متفاوت وجود داشته باشد، باید اینترفیس را مشخص کنید. تغییر اینترفیس یک حساب فعال مجاز نیست؛ این کار می‌تواند مبنای محاسبه را عوض کند.

## آزمایش‌ها

تست‌های واحد:

```bash
python3 -m unittest discover -s tests -v
```

تست‌های واقعی کرنل در محیط شبکهٔ جداگانه اجرا می‌شوند و به قوانین شبکهٔ اصلی دست نمی‌زنند:

```bash
sudo unshare --net -- python3 tests/integration_linux.py
```

این مجموعه ۱۷ تست واحد و نصب‌کننده و ۱۶ تست واقعی کرنل دارد. آزمایش‌ها شامل بایت‌های مشخص UDP در هر دو نسخهٔ IP، ترافیک TCP، ترافیک پورت نامرتبط، خواندن هم‌زمان، بازیابی پس از حذف جدول، جلوگیری از دوباره‌شماری پس از تغییر بوت و قطع‌شدن نصب یا ذخیره هستند. حفظ نسخه‌های پشتیبان و قفل نصب‌کننده هم آزمایش می‌شوند. آزمایش بازیابی جای ری‌بوت واقعی سرور را نمی‌گیرد.
